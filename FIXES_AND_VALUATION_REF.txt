1. SUMMARY OF ISSUES IDENTIFIED AND FIXED
--------------------------------------------------------------------------------

[Fix 1] Duplicate React Keys on Report Page (Console Error Resolution)
- File: app/cases/[id]/report/page.tsx
- Issue:
  The `KV` (Key-Value) component rendered rows using `key={k}` where `k` was the
  label string. When `c.details` contained details with labels matching standard
  summary rows (such as "Property" or "Location"), React produced the console
  error:
  "Encountered two children with the same key, 'Property' / 'Location'."
- Fix:
  Updated `KV` row rendering to `rows.map(([k, val], i) => <tr key={`${k}-${i}`}>`,
  guaranteeing globally unique keys for every row regardless of document metadata.

[Fix 2] Duplicate React Keys in Workbench Case Facts
- File: app/cases/[id]/page.tsx
- Issue:
  The case facts dropdown rendered `c.details.map((d) => <div key={d.label}>`.
  If multiple document facts shared the same label, it triggered duplicate key
  warnings in React.
- Fix:
  Updated to `c.details.map((d, i) => <div key={`${d.label}-${i}`}>` ensuring uniqueness.

[Fix 3] Duplicate React Keys in Floor-wise Deviation BarChart Cells
- File: components/workbench/MeasureTab.tsx
- Issue:
  Recharts `<Cell key={d.floor}>` produced duplicate keys if multiple floors
  shared a label or were added without custom names.
- Fix:
  Updated cell keys to `key={`${d.floor}-${i}`}`.

[Fix 4] Semantic Duplicate Field Cleanup in New Property Case Generator
- File: lib/data/newPropertyCase.ts
- Issue:
  `buildNewPropertyCase` added `{ label: 'Location', value: ... }` to `c.details`,
  causing duplicate "Location" entries alongside the main header Location field.
- Fix:
  Updated label to `{ label: 'Full Address', value: ... }`.

[Fix 5] Google Maps Script Loader Hang & Timeout Resilience
- File: lib/googleMaps.ts
- Issue:
  When `maps.googleapis.com` experienced connection resets (ECONNRESET), network
  firewall blocks, or billing restrictions, `loadGoogleMaps()` would remain an
  unresolved Promise with no timeout. Furthermore, `googleMapsAvailable()`
  only checked `!authFailed`, where `authFailed` was only set by `gm_authFailure`.
  This caused autocomplete and maps to hang instead of falling back to Leaflet.
- Fix:
  - Added a 4,000 ms timeout to `loadGoogleMaps()`.
  - Added `loadFailed` tracking flag. If the script times out or errors on load,
    `loadFailed = true` is set and `loadPromise` is cleaned up.
  - `googleMapsAvailable()` now returns `GOOGLE_MAPS_KEY.length > 0 && !authFailed && !loadFailed`,
    ensuring immediate, zero-lag fallback to Leaflet (Esri/OpenStreetMap) and Photon.

[Fix 6] Address Autocomplete Resilience & Enter-Key Geocoding
- File: components/AddressAutocomplete.tsx
- Issue:
  1. `googleSuggest` directly accessed `lib.AutocompleteSuggestion`, which is
     only exposed in newer Places libraries via `google.maps.importLibrary("places")`.
  2. If Photon was unavailable, autocomplete had no fallback to the internal
     geocoding API (`/api/geocode`).
  3. When an address was typed in the input, pressing `Enter` did nothing if the
     dropdown suggestions hadn't loaded yet.
- Fix:
  - Added dynamic `importLibrary("places")` loader with strict typing.
  - Added `osmSuggest` with automatic fallback to `/api/geocode?q=...` if Photon fails.
  - Added `Enter` key geocoding: pressing `Enter` now instantly geocodes the typed
    query via `geocodeText(q)` and sets the property pin and details.

3. HOW TO CREATE A NEW PROPERTY VALUATION IN THE BROWSER
--------------------------------------------------------------------------------

Step 1: Open the App
- In Chrome / your browser, go to:
  http://localhost:3000

Step 2: Start a New Valuation
- Click the "Value a New Property (Live Data)" button on the top right
  (or navigate to http://localhost:3000/value).

Step 3: Enter Location
- Type any address in India (e.g., "Civil Lines, Nagpur" or "Indira Nagar, Dehradun")
  and press Enter or click a suggestion.
- Or simply click anywhere on the interactive map to drop the pin.

Step 4: Enter Property Details
- Enter Deed Plot Area (e.g., 2,400 sqft), Approach Road width (e.g., 30 ft),
  Age (e.g., 5 yrs), Residual Life (e.g., 55 yrs), and Construction Rate.
- Specify floor areas under the Floors table.

Step 5: Attach Market Evidence
- Click "Fetch live market evidence" to automatically retrieve live listings,
  guideline rates, and auction reserves via Tavily search and extract verified rates.
- OR click "Add comparable manually" to add custom comparables.

Step 6: Review Live Engine Preview & Open Workbench
- The bottom card displays real-time Consensus Land Rate, Authenticity Score (S),
  Market Value (MV), and Risk Cascade Route.
- Click "Create case & open Workbench".

Step 7: Underwriter Workbench & Report Sign-Off
- Inspect Engine 1 (Measure & GIS), Engine 2 (Price & Stress Sliders),
  Engine 3 (Usage & Trust), and Engine 4 (Auto-QC Audit).
- Click "Preview Report & Remote e-Sign" to view the official IDFC Technical
  Appraisal Report, test the 1-click PDF download, and complete the simulated
  RBI Phase 1 OTP e-sign (Demo OTP: 654321).
